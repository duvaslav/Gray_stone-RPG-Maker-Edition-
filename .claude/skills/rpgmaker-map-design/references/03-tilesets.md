# Тайлсеты: что где лежит и что выбирать

## Сначала — инвентаризация, потом решения

Наборы листов у всех разные: RTP MV, RTP MZ, DLC, покупные паки, самодел.
**Никогда не угадывай, какие тайлсеты есть в проекте** — посмотри:

```bash
node scripts/cli.js info <проект>        # тайлсеты + карты + что вообще есть
node scripts/cli.js tilesets <проект>    # какие листы прицеплены к каждому тайлсету
node scripts/cli.js tileset <проект> 5   # породы, их номера и флаги одного тайлсета
```

`tileset` печатает номера `kind` — именно они идут в `paintAutotile` и
`buildRoom`, и именно их бесполезно угадывать по памяти.

Точные координаты конкретного стула или бочки на листе B по числам не
восстановить — их надо **посмотреть глазами**: открой `img/tilesets/<лист>.png`,
раздели на клетки 48×48 и считай столбец/ряд с нуля. Тогда id тайла —
`T.b(col, row)`.

## Роли листов

| Лист | Тип | Назначение | Практика |
|---|---|---|---|
| **A1** | автотайл, анимированный | вода, лава, водопады | 16 пород; чётные — поверхность, нечётные (от 4) — водопады |
| **A2** | автотайл | земля, полы, тропинки, трава | главный «материал» карты; 32 породы |
| **A3** | автотайл | крыши и внешние стены домов | блок 2×2, укладывается кратно 2 тайлам |
| **A4** | автотайл | стены помещений и утёсов | чётные ряды — верх стены, нечётные — грань |
| **A5** | обычные | «плоская земля» без автотайла | одиночные полы, куда автотайл не нужен |
| **B** | обычные | основной декор темы | мебель, двери, окна, мелочь |
| **C** | обычные | продолжение декора | крупные объекты, деревья |
| **D** | обычные | обычно тематический декор | часто пусто у интерьеров |
| **E** | обычные | добавочный декор | часто пусто |

**A3 и A4 — не взаимозаменяемы.** A3 — «здание снаружи»: крыша + фасад, кладётся
блоками 2×2. A4 — «стена изнутри»: верх стены (рисуется как пол, семейство floor)
и грань стены (семейство wall). Если поставить A4-грань там, где нужен A3-фасад,
получится стена без верхних краёв.

## Типовые наборы RTP

В стандартных проектах листы называются по схеме `<Тема>_<Лист>`:
`Inside_A2`, `Inside_A4`, `Inside_B`, `Outside_A1…A5`, `Outside_B`, `Outside_C`,
`Dungeon_A1…A5`, `Dungeon_B`, `Dungeon_C`, `World_A1`, `World_A2`, `World_B`,
плюс фантастические наборы с префиксом `SF_` (в MZ они основные для sci-fi тем).
**Состав проверяй командой `tilesets`** — набор зависит от версии и купленных DLC.

Как выбирать тайлсет под сцену:

| Сцена | Что брать |
|---|---|
| комната, дом, трактир, лавка | «интерьерный» тайлсет: A2 полы + A4 стены + B мебель |
| улица города, деревня | «внешний»: A1 вода, A2 земля/дороги, A3 дома, A4 заборы/утёсы, B–C декор |
| подземелье, пещера | «подземный»: A2 пол, A4 стены, A1 лава/вода, B двери и ловушки |
| глобальная карта | «мировой» тайлсет, у него `mode: 0` |

Смешивать листы из разных тем в одном тайлсете можно и нужно — тайлсет это
просто набор из 9 картинок. Но следи за палитрой и размером «пикселя»: тайлы
из наборов разных художников рядом смотрятся как заплатки.

## Один тайлсет на карту

Карта ссылается на **один** `tilesetId`. Если для сцены нужны мебель из
интерьерного B и растения из внешнего C — заводи в базе данных новый тайлсет,
где нужные листы собраны вместе. Плодить тайлсеты дешевле, чем городить
костыли: движок хранит только имена файлов и флаги.

Заводя новый тайлсет, не забудь проставить флаги: у свежего все нули, то есть
вся мебель будет проходимой насквозь.

## Проверка того, что получилось

```bash
node scripts/cli.js preview <проект> <mapId> -o /tmp/map.html
```

Рендерит карту той же математикой, что и движок, с оверлеями проходимости,
регионов, теней и событий. Это единственный способ увидеть, что автотайлы
сошлись, не запуская редактор.
