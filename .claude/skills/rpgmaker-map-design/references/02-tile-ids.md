# Тайловые ID, автотайлы и флаги

Числа ниже — из `Tilemap` в `rmmz_core.js`. Для MV они те же.

## Диапазоны ID

| Диапазон | Лист | Кол-во | Что это |
|---|---|---|---|
| `0 … 255` | B | 256 | обычные тайлы (декор) |
| `256 … 511` | C | 256 | обычные тайлы |
| `512 … 767` | D | 256 | обычные тайлы |
| `768 … 1023` | E | 256 | обычные тайлы |
| `1024 … 1535` | — | — | не используется |
| `1536 … 1663` | A5 | 128 | обычные тайлы «земли» (не автотайл) |
| `2048 … 2815` | A1 | 16 пород | вода и водопады (анимированные) |
| `2816 … 4351` | A2 | 32 породы | земля, полы, тропинки |
| `4352 … 5887` | A3 | 32 породы | крыши и внешние стены зданий |
| `5888 … 8191` | A4 | 48 пород | стены (верх + грань) |

`0` — пустая клетка. Левый верхний тайл листа B недоступен: его id равен нулю.

### Обычные тайлы (A5, B–E)

Лист B–E — 16 столбцов × 16 рядов, A5 — 8 × 16. Позиция → id:

```js
id = base + (col >= 8 ? 128 : 0) + row * 8 + (col % 8)   // B:0 C:256 D:512 E:768
id = 1536 + row * 8 + col                                 // A5, col 0..7
```

В библиотеке: `T.b(col,row)`, `T.c(...)`, `T.d(...)`, `T.e(...)`, `T.a5(col,row)`.
Обратно — `T.atlasPos(id)`.

### Автотайлы (A1–A4)

```js
kind  = Math.floor((id - 2048) / 48)   // «порода»: какая именно земля/стена
shape = (id - 2048) % 48               // как обрезаны края, считается автоматически
id    = 2048 + kind * 48 + shape
```

`kind` нумеруется сквозь все автотайловые листы, по 8 пород в ряду палитры:

| kind | Лист | Роль | Блок на листе |
|---|---|---|---|
| 0–15 | A1 | вода (чётные) и водопады (нечётные, начиная с 4) | особый |
| 16–47 | A2 | пол/земля | 2×3 тайла |
| 48–79 | A3 | чётный ряд — крыша, нечётный — внешняя стена | 2×2 тайла |
| 80–127 | A4 | чётный ряд — **верх стены**, нечётный — **грань стены** | 2×3 / 2×2 |

Помощники: `T.a1Kind(col,row)`, `T.a2Kind(col,row)`, `T.a3Kind(col,row)`,
`T.a4Kind(col,row)` — col 0..7, row считается внутри своего листа.

Проверки принадлежности: `T.isWallTop`, `T.isWallSide`, `T.isRoof`,
`T.isWaterfall`, `T.isFloorType`, `T.isWallType`.

## Как работают формы (shape)

Тайл собирается из **четырёх четвертей**, взятых из блока породы по таблице.
Есть три таблицы:

- `FLOOR_AUTOTILE_TABLE` (48 форм) — вода A1, полы A2, **верх стены A4**;
- `WALL_AUTOTILE_TABLE` (16 форм) — крыши и стены A3, **грань стены A4**;
- `WATERFALL_AUTOTILE_TABLE` (4 формы) — водопады.

### Правила подбора

**Половое семейство.** Для каждого угла смотрим на двух соседей, которые его
касаются, и на диагональ между ними. Диагональ учитывается, только если оба
соседа связаны (`nw = nw && n && w`). Дальше угол принимает одно из состояний:
сплошной / внутренний угол / вертикальная кромка / горизонтальная кромка /
внешний угол. Опорные значения:

| Соседи | shape |
|---|---|
| все восемь | 0 |
| нет NW / NE / SE / SW | 1 / 2 / 4 / 8 (биты складываются) |
| нет W / N / E / S | 16 / 20 / 24 / 28 |
| нет N и S (горизонтальный коридор) | 33 |
| нет N и W (внешний угол) | 34 |
| нет ни одного соседа | 46 |

Форма 47 — «плоский» тайл из левого верхнего угла блока; редактор при обычной
укладке её не выдаёт, но она валидна.

**Настенное семейство.** Диагонали не учитываются, форма — просто битовая маска
«соседа нет»: `W=1, N=2, E=4, S=8`. То есть 0 — окружён со всех сторон, 15 —
одиночный столб.

**Водопад.** Только горизонталь: `W=1, E=2`.

Связными считаются соседи **той же породы** (тот же `kind`). Другая порода —
это край, там появится кромка.

В библиотеке всё это делает `map.solveShape(x,y,z)`; после любой правки
автотайлов зови `map.refreshAutotiles(rect, z)` — иначе на стыках останутся
рваные швы. `paintAutotile`, `putAutotile` и `buildRoom` пересчитывают сами.

## Флаги тайлсета

`Tilesets.json → flags[tileId]`, битовая маска:

| Бит | Значение |
|---|---|
| `0x0001` | нельзя пройти вниз ↓ |
| `0x0002` | нельзя пройти влево ← |
| `0x0004` | нельзя пройти вправо → |
| `0x0008` | нельзя пройти вверх ↑ |
| `0x0010` | ★ — рисуется над героем, **на проходимость не влияет** |
| `0x0020` | лестница (герой стоит спиной) |
| `0x0040` | куст (нижняя половина спрайта полупрозрачна) |
| `0x0080` | прилавок (можно говорить через тайл); для A2 ещё и режим «стол» |
| `0x0100` | урон при ходьбе |
| `0x0200` / `0x0400` | непроходим для лодки / корабля |
| `0x0800` | дирижабль не сядет |
| `0xF000` | terrain tag 0..7 (`flag >> 12`) |

`0x000F` = все четыре направления = «полностью непроходим».

### Как движок решает, можно ли пройти

`Game_Map.checkPassage` идёт по слоям **сверху вниз** (z3 → z0) и
останавливается на **первом** тайле, который «высказался»:

- флаг содержит ★ → тайл пропускается;
- проверяемый бит не выставлен → **проходимо**, дальше не смотрим;
- бит выставлен → **непроходимо**, дальше не смотрим.

Отсюда два следствия, на которых спотыкаются постоянно:

1. **Декор поверх стены может сделать стену проходимой.** Если положить на
   стену тайл с флагом «проходим», он перебьёт стену снизу. Поэтому настенный
   декор (окна, картины, вывески) должен иметь ★ либо запрет прохода.
   `map.validate()` ловит этот случай отдельным предупреждением.
2. **Пустая клетка (id 0) ничего не решает** — у неё в базе стоит ★.

`terrainTag` и флаги «лестница / куст / прилавок / урон» читаются иначе: они
проверяются по **всем** четырём слоям сразу (`checkLayeredTilesFlags`), первый
ненулевой terrain tag сверху вниз и побеждает.

## Быстрая шпаргалка «что куда класть»

| Хочу | Слой | Флаг тайла |
|---|---|---|
| пол, по которому ходят | z0 | проходим |
| стена | z0 | 0x0F |
| ковёр поверх пола | z1 | проходим |
| стол, шкаф (обходят) | z1 | 0x0F |
| крона дерева, верх арки | z2/z3 | ★ |
| картина на стене | z1/z2 | ★ (иначе стена станет проходимой) |
| прилавок, через который говорят | z1 | 0x0F + 0x80 |
| куст, скрывающий ноги | z1 | проходим + 0x40 |
