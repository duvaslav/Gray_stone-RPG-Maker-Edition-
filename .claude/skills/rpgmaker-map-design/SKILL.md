# Проектирование карт RPG Maker MV / MZ

Скилл покрывает всю цепочку: понять, что есть в проекте → спланировать карту →
собрать её кодом → проверить → посмотреть глазами.

MV и MZ хранят карты одинаково, поэтому код общий; различия отмечены отдельно.

## С чего начинать всегда

**Не угадывай содержимое проекта.** Наборы тайлсетов, их номера и координаты
мебели на листах у всех разные. Первым делом:

```bash
node .claude/skills/rpgmaker-map-design/scripts/cli.js info <путь-к-проекту>
node .claude/skills/rpgmaker-map-design/scripts/cli.js tileset <путь-к-проекту> <id>
```

`info` покажет движок (MV/MZ), тайлсеты, карты и свободный id.
`tileset` — какие листы прицеплены, номера автотайловых пород (`kind`) и флаги.

Координаты конкретного предмета на листе B–E по числам не восстановить.
Либо открой `img/tilesets/<лист>.png` и посчитай клетки 48×48 (столбец и ряд
с нуля → `T.b(col, row)`), либо возьми готовые id из существующей карты
проекта — часто это быстрее и надёжнее.

## Рабочий цикл

1. **Задача.** Что за сцена, что игрок должен здесь сделать, куда пойдёт дальше.
2. **Инвентаризация** (`info`, `tileset`), выбор тайлсета — `references/03-tilesets.md`.
3. **Планировка на бумаге**: список содержимого → размер карты → силуэт → маршрут.
   Принципы и чек-лист — `references/04-design-principles.md`.
4. **Сборка кодом** (`scripts/rpgmap.js`) или правка существующей карты.
5. **Интерактив**: события-объекты — `references/05-interactive-objects.md`.
6. **Проверка**: `cli.js validate` — швы автотайлов, проходимость, события.
7. **Просмотр**: `cli.js preview` → html, открывается в браузере.

Пункты 3 и 6 не пропускай: без планировки получается коробка, без проверки —
рваные швы и стены, сквозь которые ходят.

## Библиотека

`scripts/rpgmap.js`, без зависимостей, вся арифметика выведена из корескрипта.

```js
const { Project, RMMap, T, Z, Ev, Cmd } = require("./scripts/rpgmap");

const project = new Project("/путь/к/проекту");
const map = RMMap.create({ width: 15, height: 10, tilesetId: 5 });
map.project = project;

// Комната: buildRoom принимает прямоугольник ПОЛА и сам достраивает
// грань стены сверху и верх стены по периметру
map.buildRoom({ x: 1, y: 2, w: 13, h: 7 }, {
  floorKind:    T.a2Kind(0, 0),   // порода пола из листа A2
  wallTopKind:  T.a4Kind(0, 0),   // чётный ряд A4 — верх стены
  wallSideKind: T.a4Kind(0, 1),   // нечётный ряд A4 — грань стены
});

map.paintAutotile({ x: 10, y: 2, w: 3, h: 2 }, Z.LOWER, T.a2Kind(1, 0)); // другой пол
map.set(6, 5, Z.LOWER2, T.b(0, 8));      // декор на втором нижнем слое
map.castWallShadows();                    // тени от стен по всей карте
map.setRegion(7, 8, 1);                   // метка региона

map.addEvent(Ev.event({ name: "Свеча", x: 5, y: 3, pages: [pageOff, pageOn] }));

console.log(map.toAscii());
console.log(map.validate());
project.writeJson(project.mapFileName(7), map.toJSON());
project.registerMap(7, "Таверна", { parentId: 0 });   // иначе карты не будет в дереве
```

Основное API:

| Что | Как |
|---|---|
| открыть проект / карту | `new Project(dir)`, `project.loadMap(id)` |
| создать карту | `RMMap.create({width, height, tilesetId})` |
| тайл | `map.get(x,y,z)`, `map.set(x,y,z,id)` |
| прямоугольники | `fill`, `outline`, `forRect`, `scatter` |
| автотайлы | `paintAutotile(rect,z,kind)`, `putAutotile`, `refreshAutotiles` |
| комната | `buildRoom(полRect, {floorKind, wallTopKind, wallSideKind, faceHeight})` |
| штамп объекта | `stamp(x, y, {w, h, layers})` |
| тени / регионы | `castWallShadows()`, `setShadow`, `setRegion` |
| события | `addEvent`, `Ev.event`, `Ev.page`, `Ev.tileImage`, `Cmd.*` |
| анализ | `validate()`, `stats()`, `toAscii()`, `reachable()`, `isWalkable()` |
| id тайлов | `T.b/c/d/e(col,row)`, `T.a5(col,row)`, `T.a1Kind/a2Kind/a3Kind/a4Kind` |
| слои | `Z.LOWER` 0, `Z.LOWER2` 1, `Z.UPPER` 2, `Z.UPPER2` 3, `Z.SHADOW` 4, `Z.REGION` 5 |

Рабочий пример целиком — `scripts/examples/tavern-room.js` (зал таверны с
мебелью, двумя свечами, сундуком, дверью и полкой). Запускается без `--write`
как сухой прогон.

Проверка самой библиотеки: `node scripts/selftest.js` (24 проверки, включая
все 256 комбинаций соседей автотайлов).

## Инструменты

```bash
node scripts/cli.js info      <проект>                     обзор проекта
node scripts/cli.js tilesets  <проект>                     тайлсеты и их листы
node scripts/cli.js tileset   <проект> <id>                породы, kind'ы, флаги
node scripts/cli.js map       <проект> <mapId>             сводка, схема, события
node scripts/cli.js validate  <проект> [mapId|all]         проверки
node scripts/cli.js preview   <проект> <mapId> [-o f.html] визуальный рендер
node scripts/cli.js fix       <проект> <mapId> [--write]   пересчёт швов автотайлов
```

`preview` рисует карту той же математикой, что и движок, с оверлеями
проходимости, регионов, теней и событий — это способ увидеть результат, не
открывая редактор.

## Правила, которые экономят часы

1. **Пиши JSON одной строкой** (`JSON.stringify(obj)` без отступов) — так пишет
   редактор; иначе первый же его запуск переформатирует файл.
2. **Карта должна быть в `MapInfos.json`**, иначе её не видно в дереве.
3. **После любой правки автотайлов — `refreshAutotiles()`**, иначе на стыках
   останутся видимые швы. `paintAutotile`/`buildRoom` делают это сами.
4. **Длина `data` строго `width*height*6`**; меняешь размер — через `resize()`.
5. **`events[i].id` обязан равняться `i`**, `events[0]` всегда `null`.
6. **Список команд события кончается `{"code":0}`**.
7. **Декор поверх стены может сделать стену проходимой** — движок берёт первый
   «высказавшийся» тайл сверху вниз. Настенным украшениям нужен флаг ★.
8. **Не редактируй карту, открытую в редакторе** — он перезапишет файл своим
   состоянием. Закрой проект или хотя бы карту.
9. **Делай бэкап перед записью** в существующий проект (`cli.js fix --write`
   складывает `.bak` сам; свой код — коммить проект в git заранее).
10. **Автозапуск (trigger 3), не снимающий себя переключателем, вешает игру.**
